# Migración a la base endurecida

Base previa: commit `1278db4`. No se modificaron datos runtime ni se copiaron secretos. Esta migración exige revisión y autorización del operador, no se ejecuta automáticamente.

1. Inventariar procesos existentes, listeners, VMs y redes desde consola autorizada. Detener el arranque automático heredado y aislar/apagar señuelos por herramienta del hipervisor; no confiar en PID guardado. La API nueva **no detendrá automáticamente** VMs antiguas.
2. Respaldar usuarios/configuración/SQLite con procedimiento consistente y acceso restringido. No incorporar credenciales/capturas al repositorio o bundle. Mantener los originales en frío. **Revisar permisos de las bases**: los almacenes nuevos rechazan SQLite accesible por grupo/otros (habitual `0644`); si no se corrige a `0600` con el propietario del servicio, auditoría y alertas fallan cerradas (visible como `storage_errors` en `/api/health`). Ver [operaciones](<docs/HARDENING-OPERATIONS.md>).
3. Provisionar el despliegue siguiendo [operaciones](<docs/HARDENING-OPERATIONS.md>). Crear JWT único y administrador local. No copiar token compartido de ingestión. Eliminar contraseñas en claro del YAML mediante migración local revisada; autenticación ya no las convierte automáticamente.
4. Las variables de entorno se suministran explícitamente por servicio; no hay auto-carga de `.env`. Los flags antiguos no reactivan listeners, tailers, QEMU, firewall ni supresión IA.
5. JWT anteriores deben renovarse: se comprueba usuario/rol/versión de contraseña vigente. Borrar usuario, cambiar rol o contraseña invalida la sesión. **Los tokens solo son válidos si los emite `/api/auth/login`**; cualquier token fabricado a mano o por herramienta externa sin el claim de versión de credenciales obtiene 401 (ruptura verificada en ejecución). API keys heredadas requieren revisión y revocación manual; no se crean por defecto.
6. `/api/deception/ingest` devuelve 410 sin fallback JWT; migrar al servicio HTTPS separado `/v1/events`. Formato exacto `{version:1,events:[...]}`, ID UUID4 estable durante retry, dispositivo asignado, timestamp con zona e IP canónica. No enviar `sensor_id`, `simulated`, usuario administrativo ni credenciales de control. Ver [contrato](<runtime/contracts.py>).
7. Una credencial distinta por sensor, rotación/revocación locales; certificado y CA por canal seguro. No montar la base central en el sensor. Los adaptadores nativos, Cowrie/OpenCanary y Go siguen **bloqueados hasta su portado y validación**; no apuntarlos al API antigua.
8. Los históricos permanecen en su SQLite original y la API conserva consultas históricas. El almacén v1/outbox es nuevo; no se realiza conversión automática ni se borra la historia. La UI antigua no presenta eventos v1. Diagnóstico por CLI local; integración de lectura futura fuera de esta entrega.
9. Las allowlists antiguas no suprimen detección. No inferir que un evento es benigno por IP privada o flag simulado. Las futuras excepciones necesitan alcance, responsable, motivo y caducidad. IA no tiene autoridad de supresión/bloqueo/aislamiento.
10. Los endpoints de arranque de motor/tailer/VM, simulación, mutación firewall y otras acciones heredadas devuelven 409. Administración segura de dispositivos/segmentos sigue disponible, pero es solo configuración, no activación. Routers auxiliares de IA/monitorización/proxies no se registran en el control mínimo. Usuarios existentes deben usar hashes bcrypt y archivos privados.
11. Compose deception y scripts de arranque/VLAN antiguos se retiraron como rutas operativas. El resto de scripts/Compose históricos no forma parte del despliegue soportado; no ejecutarlos para eludir bloqueos.
12. Preparar laboratorio y aprobar evidencia de [validación](<docs/HARDENING-TESTS.md>) antes de implementar un cambio que permita activar. No migrar un bridge/NAT por nombre ni aceptar `isolated=true`. Las VMs no tienen autostart soportado.

Dependencias: los ficheros raíz de requirements históricos no son locks de producción. Los [pins directos candidatos](<deploy/requirements-control.in>) y su [procedencia](<docs/DEPENDENCY-PROVENANCE.md>) requieren resolución/hashlock Linux y revisión del aviso registrado antes de aprobar un bundle. No se ha instalado ni validado ese bundle aquí.
